# PURAH 1.4.2 — desktop-интеграции

Новые backend-адаптеры доступны модели как отдельные функции, а не как цепочка кликов мышью. В отсутствие подходящего API PURAH может предложить GUI-маршрут, но не должна заявлять, что уже прочла/нажала элемент, если инструмент этого не подтвердил.

## Архитектура маршрутов

| Намерение пользователя | Маршрут | Фокус и окна |
|---|---|---|
| «Проверь `ls`, прочитай файл, найди параметр» | `run_terminal_command(mode=background)` или файловые инструменты | Не открывает ничего |
| «Открой терминал и выполни...» | `run_terminal_command(mode=visible)` → `tmux` | Открывает терминал; по умолчанию возвращает фокус |
| «В **уже выделенном** терминале введи...» | `desktop_sequence(target=active)` | Короткая транзакция ввода в проверенное окно |
| «Посмотри на кнопку/меню в приложении» | `inspect_accessibility` → `accessibility_action` | Без мыши, часто без фокуса, если приложение поддерживает AT-SPI |
| «Прочитай вкладку управляемого Firefox/Chromium» | `browser_list_tabs` → `browser_read_tab` | Без фокуса; только отдельно разрешённый BiDi/CDP-профиль |
| «Найди определение функции в проекте» | `editor_code_symbols` (LSP, AST или ctags) / `editor_search_code` (`rg`) | Без IDE и фокуса |
| «Открой каталог в файловом менеджере» | `file_manager_reveal` (FileManager1 D-Bus) | Открывает окно **по запросу** |
| «Что было после прошлого запуска?» | `read_terminal_output` + SQLite tool journal | Не требует скриншота |

Инструменты возвращают `ok`, `backend`, ошибку и только те данные, которые удалось получить. Статический `read_webpage` и отдельный vision-провайдер остаются возможными запасными путями. Наличие этих инструментов не означает, что GUI любого приложения полностью автоматизируем без фокуса.

## 1. Нативный AT-SPI

Установщик для Arch добавляет `at-spi2-core`, `python-gobject`, `gobject-introspection`. Backend использует `Atspi` через GObject Introspection (без скриншота). Он ищет доступное приложение по PID из Hyprland, ограничивает обход дерева, запоминает живые элементы на 30 секунд и выполняет только явно присутствующее в `actions` действие. При нескольких окнах одного PID проверяет точное доступное имя окна; при неоднозначности отказывает. Снимок привязан к адресу Hyprland, повторное действие по старому снимку запрещено.

Проверять прямо в сессии Hyprland после запуска поддерживающего accessibility приложения. Некоторые Qt/Electron-приложения отключают или не предоставляют дерево; в этом случае придётся использовать OCR/vision или нативный API программы. Текст поля пароля намеренно не извлекается.

## 2. Браузеры: Firefox WebDriver BiDi и Chromium CDP

**Оба backend выключены по умолчанию.** В обычном Firefox без запуска Remote Agent PURAH не может прочитать вкладки из фона — и не должна притворяться, что может. Важно: протокол автоматизации даёт доступ к документам и данным авторизованного профиля. Используй **отдельный профиль**, не свой основной. Оба варианта работают через localhost, без движения мыши и без изменения фокуса, но это не механизм изоляции от других процессов текущего пользователя.

### Firefox — предпочтительный вариант для Firefox

Firefox использует **WebDriver BiDi**, а не CDP. Для отдельного профиля на Linux:

```bash
mkdir -p "$HOME/.local/share/purah/firefox-automation"
chmod 700 "$HOME/.local/share/purah/firefox-automation"
firefox --new-instance \
  --profile "$HOME/.local/share/purah/firefox-automation" \
  --remote-debugging-port=9223
```

В `~/.config/purah/config.toml`:

```toml
[browser]
automation_backend = "firefox"  # или auto, если default_browser = firefox
firefox_bidi_enabled = true
firefox_bidi_port = 9223
cdp_enabled = false
```

После перезапуска PURAH: `browser_list_tabs` получает вкладки через `browsingContext.getTree`, `browser_read_tab` читает DOM через фиксированный `script.evaluate`, `browser_navigate_tab` открывает внешний HTTP(S) адрес через `browsingContext.navigate`. Эти вызовы **не двигают мышь, не отправляют хоткеи и не переключают фокус**. Доступны только точные `tab_id` из предварительного списка. Только чтение и явно запрошенная навигация: модель не может передать произвольный JavaScript. Если в новом профиле есть только стартовая вкладка `about:home`/`about:blank`, её можно выбрать **для навигации**, но читать служебную страницу нельзя.

Каждая операция закрывает собственную BiDi-сессию. Firefox допускает только одну активную автоматизационную сессию; если её уже заняло другое приложение, PURAH вернёт ошибку и не будет вытеснять другой клиент. Нельзя добавлять `--remote-allow-hosts` или публичное сетевое прослушивание: Firefox Remote Agent не имеет встроенной аутентификации.

### Chromium — альтернативный CDP backend

```bash
chromium \
  --remote-debugging-address=127.0.0.1 \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.local/share/purah/chromium-debug"
```

```toml
[browser]
automation_backend = "chromium"
cdp_enabled = true
cdp_port = 9222
firefox_bidi_enabled = false
```

При `automation_backend = "auto"` PURAH выбирает включённый backend, соответствующий `[terminal].default_browser`; если он выключен — другой включённый. Чтобы **не путать вкладки разных браузеров**, один вызов работает только с одним выбранным backend. Старый конфиг с одним `cdp_enabled = true` продолжает работать без изменений.

`browser_list_tabs` перечисляет HTTP(S)-вкладки и стартовые вкладки, в которые разрешено перейти. `browser_navigate_tab(tab_id, url)` запускает **явно запрошенный** переход по внешнему HTTP(S) адресу, а `browser_read_tab(tab_id)` возвращает до 20 000 символов DOM-текста уже открытой страницы. После перехода дождись загрузки и вызови чтение отдельно. Служебные страницы, приватные IP, `file:` и локальные имена не подходят для чтения/навигации; DNS-имя, которое позже переадресуется в локальную сеть, универсально отследить на уровне этого фильтра нельзя — поэтому отдельный профиль обязателен.

Содержимое закрытых постов доступно только если **отдельный** профиль уже авторизован на сайте. Протокол извлекает текст DOM, а не содержимое canvas, видео, изображений и бесконечной ленты. Для визуальных случаев остаётся отдельный vision provider и ручная навигация. Если backend не включён, `read_webpage` по-прежнему читает публичные статические страницы, а обычный видимый Firefox можно наблюдать через AT-SPI/OCR/vision, когда пользователь это запросил.

Python `websocket-client` ставится через `./install.sh` либо:

```bash
./.venv/bin/python -m pip install -r requirements-desktop.txt
```

## 3. Редакторы через LSP/CLI

`editor_code_symbols(path)` извлекает символы и строки **без открытия редактора**. По умолчанию Python анализируется через `ast`; для остальных языков используется установленный Universal Ctags, если доступен. При явно заданной команде LSP используется отдельный read-only JSON-RPC клиент (initialize → didOpen → documentSymbol), который завершается после запроса. LSP может читать проект, поэтому указывай только доверенные серверы в своём конфиге:

```toml
[editor]
lsp_python_command = "pyright-langserver --stdio"
lsp_rust_command = "rust-analyzer"
lsp_typescript_command = "typescript-language-server --stdio"
```

Для поиска буквального текста по коду вызывается `editor_search_code(path, query)`: `ripgrep` выполняется как argv (без shell), с фиксированной строкой, лимитом вывода и тайм-аутом. Команды LSP **не передаются от модели**, а читаются только из локального конфига. Этот адаптер не сохраняет файл и не нажимает клавиши в редакторе.

## 4. Файловый менеджер по D-Bus

`file_manager_reveal(path, select=false)` вызывает стандартный интерфейс `org.freedesktop.FileManager1.ShowFolders` или `ShowItems` посредством `gdbus`. Он предназначен только для явного «открой папку» или «покажи файл в файловом менеджере»; для чтения структуры папок остаётся фоновый shell. Работает, только когда установленный файловый менеджер зарегистрировал `org.freedesktop.FileManager1` в пользовательской D-Bus-сессии.

## 5. Локальный журнал контекста вызовов

После успешного `init_db()` появляется таблица `tool_events` в той же SQLite-базе, что и сообщения. Максимум **300 событий**, возраст до **7 суток**; в следующем запросе модели используется до **5 последних** записей за **24 часа**. В базе сохраняются имя инструмента, короткие метаданные, статус, код возврата и ограниченные фрагменты вывода некоторых команд. **Полные тексты Telegram, содержимое прочитанных файлов, DOM страниц и изображения не записываются**; известные шаблоны секретов вырезаются из сохранённых данных, но произвольный текст stdout может содержать чувствительную информацию, не подпадающую под шаблоны.

```toml
[memory]
tool_journal_enabled = true
tool_context_max_events = 5
```

Для полной приватности выключи журнал (`false`) и удали старые записи штатным **Clear history** в PURAH (он очищает и `tool_events`). Журнал помечен в system prompt как **недоверенный** и не должен приниматься за новую команду пользователя.

## Особенности профилей браузера и безопасности

Протоколы удалённой отладки не аутентифицируются обычным способом; они открывают широкие возможности управления содержимым профиля. PURAH не включает их сама и не подключает основной Firefox/Chromium без настройки. Список вкладок теперь дополнительно **скрывает localhost, приватные IP, URL с учётными данными и внутренние страницы**. Только стандартные пустые стартовые вкладки допускаются для навигации, а не для чтения. Это не полноценная защита от DNS rebinding, редиректов и вредоносных расширений; реальная граница безопасности — изолированный профиль.

## 6. Возврат фокуса после открытия терминала

```toml
[terminal]
visible_terminal_restore_focus = true
```

При **первом** открытии managed tmux-терминала PURAH запоминает активное окно, ждёт появления терминала и возвращает фокус только если считает, что тот действительно получил фокус в результате запуска. Если ты успел вручную переключиться в редактор или другое окно, PURAH не должна перехватывать его. Дальнейшие команды через `tmux send-keys` не зависят от фокуса и не трогают мышь. `false` оставляет обычное поведение Hyprland — новый терминал может стать активным.

Это best-effort проверка по Hyprland `activewindow`, PID/классу и списку ранее существовавших окон, а **не** блокировка фокуса ОС: запуск отдельного эмулятора или нестандартный тайминг маппинга может потребовать проверки на твоей машине.

## Диагностика

Из корня проекта:

```bash
./check.sh
./.venv/bin/python main.py --print-effective-config
command -v hyprctl gdbus rg tmux
```

`./check.sh` проверяет синтаксис, схему конфигурации, AST/contracts и headless unit-тесты; он не управляет реальным Hyprland, не запускает Telegram/API и не тестирует реальный микрофон. Для AT-SPI/BiDi/CDP/D-Bus сначала убедись, что соответствующее приложение и сервис запущены, затем запроси у PURAH чтение или действие и проверь фактический результат. Наличие Python-модуля и прохождение unit-теста **не заменяет** испытание на твоём Linux.

Полезные спецификации: [AT-SPI (GNOME)](https://gnome.pages.gitlab.gnome.org/at-spi2-core/), [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/), [Freedesktop FileManager1](https://www.freedesktop.org/wiki/Specifications/file-manager-interface/), [Language Server Protocol](https://microsoft.github.io/language-server-protocol/).

### Дополнение 1.4.1: независимая tmux-сессия

Видимый managed terminal запускается через `tmux -L purah new-session -A -s purah-agent`, отдельно от tmux-сервера пользователя. Чтобы посмотреть его из другого терминала: `tmux -L purah attach -t purah-agent`. Старый `tmux new-session -s purah-agent` без `-L` не переиспользуется — это одноразовая миграция при обновлении.

Терминал запускается с очищенным окружением (в том числе без chat/vision API-ключей). Для `gnome-terminal` используется формат `--`, для `wezterm` — `start --`, для `kitty/foot/alacritty/konsole` — `-e`. Если активный tmux pane занят программой, отличной от командной оболочки, PURAH вернёт ошибку вместо ввода неизвестному процессу. Если `tmux send-keys` не выполнился, команда не считается успешно отправленной.


## Проверка готовности установки — 1.4.2

```bash
./install.sh --check
```

Это read-only диагностика, без `sudo`, установки пакетов, обращения к браузерным данным или печати API-ключей. Состояния: `OK`, `MISSING` (обязательная зависимость), `OPTIONAL` (выключено/не задано), `INACTIVE` (debug-порт не запущен) и `CONFIGURE` (требуется ручная настройка). Код 1 означает, что отсутствует обязательный компонент. Открытый TCP-порт **не** гарантирует корректное подключение к Firefox/Chromium.

На Arch `./install.sh` устанавливает базовые инструменты Hyprland/Quickshell, библиотеку AT-SPI (`python-gobject`, `at-spi2-core`), `glib2` (`gdbus`), `ripgrep`, `tmux`, `websocket-client`, Python runtime, Vosk и выбранный TTS. Отдельные профили браузера и LSP-серверы не устанавливаются автоматически: они опциональны и требуют явного включения в конфиге. Python AST/`rg` работают и без LSP.

Для фона Telegram:

```bash
./install.sh --with-telegram
./.venv/bin/python setup_telegram.py
```

`start-purah.sh` читает авторизацию по `XDG_CONFIG_HOME` (или `~/.config`) **как данные**, без `source`/`eval`; никакие секреты не передаются в `doctor.py` или в текст диалога. При наличии Telegram env установщик восстанавливает Telethon во время переустановки.
