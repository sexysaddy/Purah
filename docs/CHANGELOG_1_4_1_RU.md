# PURAH 1.4.1 — Firefox и проверка целостности

## Изменения

- Добавлен **Firefox WebDriver BiDi** с тремя существующими инструментами браузера: `browser_list_tabs`, `browser_read_tab`, `browser_navigate_tab`. Отдельная сессия на каждый запрос, локальный WebSocket, точные context ID и фиксированный JS для чтения DOM. Новая вкладка `about:home` доступна для перехода на сайт, но не для чтения.
- Появился `purah_agent/browser.py` — единая точка выбора явно разрешённого backend; `browser_common.py` — общая валидация внешних HTTP(S) URL. Chromium CDP сохранён без изменения старого конфига.
- Протоколы выключены по умолчанию: отдельный профиль браузера и явное `firefox_bidi_enabled=true` / `cdp_enabled=true`. Обычные личные вкладки пользователя не подключаются скрытно.
- JSON-схемы инструментов вынесены в `purah_agent/tool_specs.py`. Новый тест сверяет список функций со всеми обработчиками диспетчера; скрытой несуществующей функции больше не должно появляться после рефакторинга.
- Удалены неиспользуемые Qt/TTS/vision импорты из `main.py`, повторная проверка Telegram credentials и неиспользуемая локальная переменная в `_chat_completion`; исправлено открытие браузера по настройке `default_browser`.
- Уточнён системный prompt и документация, исправлено ошибочное утверждение об обработке изображений текстовой моделью DeepSeek; chat и vision остаются раздельными.
- Расширены headless-тесты на Firefox BiDi, конфигурацию и защиту от навигации на локальные адреса. Нативный запуск Firefox, реальный Hyprland и Qt/Quickshell здесь недоступны и требуют проверки на Linux пользователя.

## Дополнительный аудит и устранение регрессий

- Исправлены три устаревших регрессионных теста после переноса схем из `main.py` в `tool_specs.py`: теперь тестируется реальный контракт и диспетчер, а не прежнее расположение текста.
- Все SQLite-соединения контекста/history/journal закрываются детерминированно; устранены предупреждения Python 3.13 о незакрытой базе.
- Firefox/Chromium больше не показывают локальные, служебные или credentialed вкладки как доступные для чтения; стандартные стартовые вкладки доступны только для перехода.
- CDP WebSocket-ответы ограничены 256 KiB, валидируются до обработки и не принимаются как корректный результат при ошибке протокола.
- Видимый терминал теперь использует изолированный `tmux -L purah` и очищенное окружение без API-ключей. Поддержаны различающиеся CLI-аргументы gnome-terminal/wezterm; добавлены проверки занятого pane и статуса `send-keys`.
- Удалены два неиспользуемых импорта типов из Telegram-коннектора. Проверки модульных глобальных зависимостей после выноса UI/worker не выявили зависимостей от несуществующих имён.
- Добавлен `test_release_integrity.py` для этих краевых случаев; **125 headless-тестов проходят**. Реальное устройство ввода, Firefox и Hyprland не тестировались в этой среде.

## Настройка Firefox

См. [`INTEGRATIONS_RU.md`](INTEGRATIONS_RU.md). Включение отдельного Firefox-профиля:

```toml
[browser]
automation_backend = "firefox"
firefox_bidi_enabled = true
firefox_bidi_port = 9223
```

Если Firefox не запущен с `--remote-debugging-port=9223`, инструменты браузера возвращают ошибку, а не пытаются подключить личный профиль. Важно: **никакого переноса cookies из основного профиля**.

## Совместимость

Миграция `ensure_config.py` добавляет только отсутствующие ключи. Старый `[browser] cdp_enabled=true` по-прежнему работает, поскольку default `automation_backend=auto` выбирает единственный включённый вариант. Старые модули терминала, Telegram, TTS, wake-word и vision остаются на прежних точках вызова.
