# PURAH 1.4.2 — независимые рабочие инструменты Linux и структурированная архитектура

PURAH (бывший CHOOM) — голосовой AI-компаньон для Linux/Hyprland с Quickshell overlay, wake-word, отдельными chat/vision моделями, TTS, локальной памятью и инструментами системы. В ветке 1.4.x расширены **фоновые** способы взаимодействия: AT-SPI для доступных приложений, WebDriver BiDi для Firefox и CDP для Chromium (только отдельные профили), LSP/CLI для кода, D-Bus для файлового менеджера и SQLite-журнал вызовов. Qt UI, ModelWorker и TTS-воркеры вынесены из `main.py` в самостоятельные модули.

Исторический интерфейс/спрайт и voice follow-up из 1.3.0 сохранены. Подробности настроек и ограничений: **[`docs/INTEGRATIONS_RU.md`](docs/INTEGRATIONS_RU.md)**, архитектура: **[`docs/ARCHITECTURE_RU.md`](docs/ARCHITECTURE_RU.md)**, изменения: **[`docs/CHANGELOG_1_4_2_RU.md`](docs/CHANGELOG_1_4_2_RU.md)**.

## Выбор способа работы

Обычный `ls`, чтение конфига, поиск по коду и запуск скриптов — **фоновые операции**, ничего не открывают перед пользователем. «Открой терминал и выполни `ls`» запускает managed `tmux` в терминале и по умолчанию **пытается** вернуть фокус в исходное окно, после чего отправляет команды в tmux без мыши. «В **уже выделенном** терминале введи `ls`» означает адресный GUI-ввод в это окно. Указанное пользователем «открой папку в файловом менеджере» действительно открывает папку посредством D-Bus, а просто «проверь папку» выполняется без GUI.

Для видимого терминала с версии 1.4.1 используется отдельный сокет tmux (`tmux -L purah`), а окружение дочернего процесса очищается от переменных с API-ключами. Старая tmux-сессия без `-L purah` не будет автоматически присоединена: её можно отдельно закрыть после проверки. Если в управляемом pane сейчас запущен интерактивный процесс (например, vim), PURAH откажется вводить туда shell-команду. В фоне `ls`/чтение файлов ничего не открывает.

Для приложений по возможности применяется **нативный API** (например, опциональный Telegram-коннектор). Для доступного интерфейса — AT-SPI; для отдельного debug-профиля Firefox — WebDriver BiDi, для Chromium — CDP; для кода — AST/LSP/`rg`. Только когда эти способы не подходят, используются проверенные клавиатурные последовательности Hyprland, OCR и отдельная vision-модель. Ни один backend не гарантирует, что стороннее приложение экспортирует нужный элемент: PURAH должна честно сообщить о недоступности данных.

`main.py` остаётся совместимым с существующим `start-purah.sh` и конфигами, но содержит ещё часть STT/API-диспетчера; полностью идеальной декомпозиции пока нет. UI не импортирует `main.py` напрямую: зависимости приходят через `UiServices`. `ModelWorker` получает API-функцию через dependency injection, TTS-классы используют отдельный модуль. Это убирает наиболее тяжёлую связность, не переписывая работающий микрофонный цикл.

### Голос после ответа и закрытие

Когда текст ответа показан и TTS завершил воспроизведение, открытый overlay настраивает короткое окно `PURAH_WAKE_FOLLOWUP_SECONDS = 15`. В это время достаточно сказать «Пура» — полная фраза «Привет, Пура» не нужна. После истечения таймера снова требуется полная wake-фраза. «Пура, закройся», «Привет, Пура, закройся» и близкие команды распознаются локально и закрывают overlay без API-вызова; фраза «закрой терминал» без имени PURAH не закрывает ассистента. Закрытие сбрасывает таймер, останавливает текущий ввод/TTS и оставляет tray/listener в рабочем состоянии.

### Telegram без GUI

Опциональная установка (после обычного `./install.sh`):

```bash
./install.sh --with-telegram
./.venv/bin/python setup_telegram.py
```

При обновлении уже настроенного Telegram-коннектора `./install.sh` повторно поставит Telethon и без флага. Авторизация аккаунта всегда выполняется только вручную.

Авторизация хранится в `~/.config/purah/telegram.session` и `telegram.env` с правами `0600`. Для сообщения PURAH сначала вызывает `telegram_resolve_recipient`. Единственный точный результат можно отправить; fuzzy-совпадение вроде «Ивану Петрову» требует подтверждения, а несколько каналов «Новости-*» требуют выбора. «Избранное» разрешается специальным peer `me`. После timeout отправка не повторяется автоматически, потому что сообщение могло уже попасть в Telegram.

Коннектор умеет получить последний текстовый пост выбранного канала, после чего обычная модель пересказывает его. Закрытые каналы доступны только авторизованному аккаунту. Без Telethon/API ID/hash эти инструменты скрываются из набора функций, а обычные shell, файлы и GUI продолжают работать.

### Vision и веб-страницы

`read_webpage` извлекает публичный статический HTTP(S) текст. Для JS/авторизованных сайтов при **явном подключении отдельного Firefox BiDi либо Chromium CDP debug-профиля** можно читать открытые вкладки и открывать внешние HTTP(S) URL через соответствующий протокол без мыши и OCR. Основной браузер пользователя не подключается автоматически. Иначе остаются `inspect_active_window` и OCR видимого текста либо явный vision-провайдер для вопроса по экрану. Текстовая DeepSeek-модель сама изображения не обрабатывает; снимок уходит только маршруту `[vision]`, а терминальный вывод и OCR остаются текстовыми локальными путями.

### Desktop-интеграции 1.4.1

Настройки в `~/.config/purah/config.toml` (показывается только то, что требуется включить вручную):

```toml
[terminal]
visible_terminal_restore_focus = true

[browser]
automation_backend = "auto"
firefox_bidi_enabled = false
firefox_bidi_port = 9223
cdp_enabled = false
cdp_port = 9222

[editor]
lsp_python_command = ""
lsp_rust_command = ""
lsp_typescript_command = ""

[memory]
tool_journal_enabled = true
tool_context_max_events = 5
```

AT-SPI не требует vision-модели: `inspect_accessibility` возвращает семантические элементы с точными `node_id` и `actions`. Firefox BiDi/CDP **опциональны и выключены**, чтобы не раскрывать основной браузер. `editor_code_symbols` и `editor_search_code` работают в фоне (AST/LSP/ctags и `rg`). `file_manager_reveal` использует `gdbus` только по просьбе открыть менеджер файлов. В памяти сохраняются короткие результаты некоторых действий, но не тела Telegram-сообщений, прочитанных файлов и DOM. Подробные инструкции и ограничения — в [`docs/INTEGRATIONS_RU.md`](docs/INTEGRATIONS_RU.md).

## Главное изменение интерфейса: Quickshell layer overlay

В режиме автозапуска глаз и диалог принадлежат **Quickshell `PanelWindow` на `WlrLayer.Overlay`**, а не обычным Qt toplevel-окнам. Виджет остаётся поверх окон и вне 3D-преобразования Hyprland. Клик вне области глаза/диалога проходит в приложение под ним и **не закрывает Пуру**; закрыть обе части можно клавишей Escape, пока фокус находится на виджете, или крестиком в шапке диалога. Ввод в поле чата по запросу получает клавиатурный фокус, но overlay больше не забирает клавиатуру в эксклюзивный режим. Python управляет микрофоном, API, локальной памятью, инструментами и озвучкой, а Quickshell рисует overlay и пересылает команды через приватные JSON-файлы в `$XDG_RUNTIME_DIR/purah/`.

В версии 1.1.4 окно диалога получило угловой HUD в стиле Capricorn, но с палитрой шиика: тёмная панель, бирюзовые контуры, золотые отметки и полосовой индикатор. Сам герб меняет цвет по состоянию; цветного кольца вокруг него больше нет. Короткие хроматические сдвиги, горизонтальные разрывы и вспышки вдохновлены глитч-эффектами Capricorn.

Для анимации Пуры используются нарезанные прозрачные кадры `purah_phoneme_*.png` и `purah_blink_*.png`, лежащие в `assets/` и дублирующиеся в `quickshell/purah/`. В ожидании, во время слушания, распознавания и подготовки ответа проигрывается естественное моргание: открытые глаза → полуоткрытые → закрытые → полуоткрытые → открытые; изредка используются дополнительные улыбка/прищур. Только в режиме `SPEAKING` рот меняется по группам букв (А/Я, О/Ё, У/Ю и т. д.) на основе текста текущего ответа. TTS не предоставляет UI пер-фонемных таймкодов, поэтому это текстово-темповая визуальная аппроксимация, не вмешивающаяся в аудио. Исходные три PNG сохранены как legacy-ассеты. Глитч по-прежнему смещает силуэт и рисует короткие scanline-разрывы. При запросе зрения Quickshell HUD не скрывается и не монтируется заново, поэтому диалог не должен мигать; модели дано указание игнорировать собственный HUD на снимке. Детектор пробуждения принимает только завершённые фразы; одиночное «Пура» и `[unk]` убраны из фоновой грамматики.

Для persistent/hotkey запуска `start-purah.sh` требует Quickshell и LayerShell: если `qs` отсутствует или QML не загрузился, запуск завершится с понятной ошибкой. Он намеренно НЕ открывает Qt fallback, чтобы Purah не превращалась в обычное окно с blur и не попадала в 3D-пространство. Старые процессы backend/Quickshell из предыдущей версии заменяются при обновлении: IPC-сокет версионирован, а версию QML launcher сравнивает с `main.py`. Для виджета установи Quickshell: `sudo pacman -S --needed quickshell`.

В режиме трей-демона Escape, когда фокус находится на виджете, или крестик закрывают текущую сессию — фоновый процесс остаётся ждать «Привет, Пура». Клик по другому приложению не закрывает виджет. Чтобы полностью остановить Purah и освободить всю память, выбери Quit/Выход в меню значка Purah в трее. Во время ответа можно перебить голосом: скажи поверх её речи «Привет, Пура» (или «Пура, стоп»), либо нажми на глаз/повтори Hyprland-бинд. Звук остановится сразу, генерация и пословный вывод старого ответа отменятся, а микрофон начнёт записывать новую команду. В режиме перебивания Vosk слушает только явную фразу, а не одиночное «Пура», чтобы уменьшить самосрабатывание на голос из динамиков.

## Установка на Arch Linux

Сначала закрой старый CHOOM/PURAH из меню трея, чтобы миграция конфигурации и истории не столкнулась с работающим старым процессом. Затем из корня клонированного репозитория запусти один установщик:

```bash
./install.sh
```

После установки или для проверки существующей копии:

```bash
./install.sh --check
```

Это **не установка**: диагностика не требует `sudo`, не вызывает `pip`, не открывает браузер и не печатает API-ключи. Она отдельно показывает обязательные зависимости, включённые/отключённые адаптеры Firefox BiDi и Chromium CDP, наличие AT-SPI, `rg`, `gdbus`, tmux, выбранной TTS/Vosk-модели и настроенных LSP-серверов. Состояние `INACTIVE` у браузера значит лишь, что порт сейчас закрыт; проверка открытого порта ещё не подтверждает корректную WebDriver/CDP-сессию.

**Что устанавливается:** на Arch `./install.sh` ставит Quickshell, Python-окружение, WebSocket-клиент для BiDi/CDP, AT-SPI, `wtype`, `grim`, `tesseract` с языками, `tmux`, `ripgrep`, `glib2` (`gdbus`), Vosk и выбранный TTS. **Что требует твоего решения:** установка отдельного браузера и запуск debug-профиля, настройка LSP-серверов, Telegram-авторизация и ключи API для чата, STT, vision. Telegram-пакеты можно поставить через `./install.sh --with-telegram`; Piper/Kokoro устанавливаются при выборе движка в меню.

`ensure_config.py` теперь физически дописывает отсутствующие секции `[browser]`, `[editor]`, `[memory]`, `[ui]` и параметр `[terminal].visible_terminal_restore_focus` в существующий `~/.config/purah/config.toml`, при этом **не перезаписывает** заданные значения. Перед первым изменением сохраняется `config.toml.pre-purah-update`; повторный запуск не плодит дубликаты.

На Arch Linux и производных он сам установит системные зависимости через `pacman` (включая Quickshell, `grim` и eSpeak NG), создаст изолированный `.venv`, поставит Python-зависимости, скачает русскую модель Vosk для фразы пробуждения и предложит выбрать TTS: Edge, Piper, eSpeak NG, Kokoro-ru или без озвучки. При выборе Piper/Kokoro установщик скачает нужные файлы модели; Edge — вариант по умолчанию без локальной TTS-модели. Повторный запуск сохранит выбранный движок в меню по умолчанию.

После установки открой `~/.config/purah/config.toml` и укажи свой ключ в `[api].api_key`. Шаблон уже настроен на `https://api.deepseek.com/chat/completions` и `deepseek-flash`; если выбираешь другого провайдера, меняй endpoint и model вместе. При обновлении со старой стандартной пары Groq + `openai/gpt-oss-120b` миграция переводит только эту известную пару на DeepSeek и делает резервную копию `.toml.pre-purah-update`; нестандартные endpoint/model сохраняются, пользовательский ключ не перезаписывается — проверь, что он именно от DeepSeek. `[api]`, `[vision]` и `[speech]` используют отдельные endpoint/model/API-key. Укажи `vision.chat_url`, `vision.model`, `vision.api_key` для снимков и `speech.stt_api_key` для STT (Groq). Ключ текста не переносится в другие сервисы. Только явный `vision.inherit_api = true` разрешает vision наследовать настройки текста. Непустые `vision`-поля всё равно переопределяют их; ключ текста можно переиспользовать только при совпадении scheme + hostname + port; для другого origin нужен отдельный `vision.api_key`. Не добавляй пользовательский конфиг с ключами в Git. Для других дистрибутивов установщик не выполняет автоматическую установку системных пакетов: нужные зависимости придётся установить вручную, после чего можно повторить `./install.sh`.

### Автозапуск Hyprland без ручной активации venv

Добавь в `~/.config/hypr/hyprland.conf`:

```ini
exec-once = /home/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/Purah/start-purah.sh
```

Заменить нужно только абсолютный путь. **Вручную входить в venv не требуется:** launcher напрямую запускает `~/Purah/.venv/bin/python`. Это остаётся изолированным окружением, но никакого `source .venv/bin/activate` при старте сессии нет. Не устанавливаем Python-зависимости в системный Python Arch, чтобы не конфликтовать с externally-managed окружением.

Для одиночного голосового вызова без постоянного wake-word используй `./run-purah.sh`. Оно также запускает Quickshell overlay и внутренний Python без ручной активации окружения; обычное Qt-окно больше не используется как fallback.

### Миграция со старого CHOOM

При первом запуске `start-purah.sh` запускает `ensure_config.py --migrate-data`:

- копирует старые настройки `~/.config/choom/` в `~/.config/purah/`, только если новый файл ещё не существует;
- обновляет внутри конфигурации только известные пути `~/.local/share/choom/` → `~/.local/share/purah/`;
- переносит отсутствующие каталоги моделей из `~/.local/share/choom/` без перезаписи уже существующих файлов;
- копирует прежнюю SQLite-историю, только если новая база отсутствует или пуста, оставляя старую базу на месте;
- создаёт резервную копию config перед редактированием. API-ключ и пользовательские промпты не заменяются шаблоном.

## Настройки

Главный файл: `~/.config/purah/config.toml`. В нём находятся API и STT, wake word, TTS, терминальный агент, общий prompt и отдельный prompt vision. Чтобы проверить, куда реально направляются запросы (без показа секретов), выполни `./.venv/bin/python main.py --print-effective-config`; 401 в новом релизе включает тип запроса, endpoint и model.

- `[assistant].system_prompt` — характер Пуры и правила обычного общения. Базовый стиль — до трёх коротких предложений без лишних вступлений/заключений и декоративной разметки. В приложении есть дополнительное правило краткости даже при старом промпте.
- `[vision].system_prompt` — отдельный стиль ответов по экрану: отвечать строго на вопрос, в 1–3 предложениях, не расписывать весь экран и не предлагать не запрошенные варианты.
- `[api]` — основной провайдер/модель и tool calling; шаблон использует DeepSeek `deepseek-flash` для текста и действий. `[vision]` отдельно настраивает endpoint/model/key для снимков (шаблон: Groq + `qwen/qwen3.8-27b`); `[speech]` отдельно настраивает endpoint/model/key для распознавания речи. Между провайдерами нет скрытого fallback ключей. Только `vision.inherit_api = true` явно разрешает наследование настроек текста; ключ не передаётся на другой origin (схема, hostname или порт). STT использует только `[speech].stt_api_key`.
- `[speech]` — отдельные настройки распознавания речи. Wake word через Vosk обрабатывается локально; команда отправляется STT только после фразы «Привет, Пура».
- `[terminal]` — системные команды и файловые действия. При `enabled = true`, `full_access = true`, `allow_sudo = true` инструменты могут читать доступные пользователю файлы (кроме защищённых хранилищ секретов), создавать/изменять файлы вне папки проекта, создавать каталоги, удалять явно запрошенные пути, запускать произвольные программы и исполнять shell-команды без подтверждения каждой команды. Изменения существующих файлов через инструмент получают локальную резервную копию. Для административных действий используется `sudo -A` с локальным графическим запросом пароля; Purah не получает пароль и не отправляет его API. Опасные/необратимые команды выполняются только по прямому запросу пользователя. Выставь `full_access = false`, чтобы вернуть ограниченный режим с подтверждениями.


### DeepSeek и системные инструменты

`[api].thinking_mode = "disabled"` рекомендуется для быстрых действий в GUI. При `"enabled"` Purah сохраняет `reasoning_content` в отдельном скрытом поле локальной SQLite-истории и возвращает его DeepSeek между раундами tool-calling; это увеличивает задержку и объём контекста. Когда DeepSeek работает в thinking-режиме, Purah не посылает явный `tool_choice` и использует автоматический выбор функций при наличии `tools`.

## TTS: выбор движка, ресурсы и настройка

Установщик предлагает четыре движка и отключённую озвучку:

| Движок | Интернет | Расход памяти | Звучание |
|---|---|---|---|
| `edge` | Нужен | Низкий: аудио синтезируется в сети | Естественный русский голос, по умолчанию Svetlana |
| `piper` | Не нужен после загрузки модели | Низкий/умеренный | Локальный голос; имя голоса определяется ONNX-моделью |
| `espeak_ng` | Не нужен | Очень низкий | Синтетический, роботизированный голос; поддерживает варианты вроде `ru+f3` |
| `kokoro_ru` | Не нужен после загрузки файлов | Самый высокий из этих вариантов | Более естественный локальный русский голос |
| `none` | — | Минимальный | Без озвучки |

Текущий движок выбирается в `~/.config/purah/config.toml`:

```toml
[tts]
enabled = true
engine = "piper" # edge, piper, espeak_ng, kokoro_ru, none
voice = "ru-RU-SvetlanaNeural" # применяется к Edge; Piper берёт голос из модели
rate = "+5%"
volume = "+0%"
espeak_voice = "ru+f3" # используется только с espeak_ng; обычный вариант — ru
piper_binary = "piper"
piper_model = "~/.local/share/purah/piper/ru_RU-irina-medium.onnx"
chunk_chars = 140
kokoro_model_dir = "~/.local/share/purah/kokoro-ru"
kokoro_voice = "masha" # masha или sveta
kokoro_speed = 1.10
kokoro_threads = 4
warmup_on_start = false
```

`./setup_piper_tts.sh` скачивает и проверяет Piper + русскую модель Irina, а затем сам выбирает `engine = "piper"` в конфиге. Настройки `rate` и `volume` применяются через `SynthesisConfig`, когда установленная версия Piper поддерживает API синтеза; `piper_binary` оставлен только для совместимости и напрямую не запускается. `./setup_kokoro_ru.sh` устанавливает Kokoro-ru и выбирает его. `espeak_ng` поставляется системным пакетом `espeak-ng`; никаких дополнительных Python-моделей для него не нужно.

**Приоритет конфигурации:** если существует `~/.config/purah/config.toml`, это единственный источник настроек. Значения, которые ты не указал, берутся из `config.toml.example`; экспортированные переменные окружения, старые `CHOOM_*` и `~/.config/purah/env` не могут вернуть старую модель, API, TTS или режим доступа. API-ключ тоже задаётся в `[api].api_key` (файл защищён правами `0600`), не только в shell env. Пустой обязательный endpoint или `api.model` не приводит к откату на старого провайдера: конфигурация отклоняется с понятной ошибкой. При изменении конфига перезапусти `./start-purah.sh` — backend сравнивает отпечаток конфигурации и заменяет устаревший процесс. Для диагностики эффективного провайдера и моделей запускай `./.venv/bin/python main.py --print-effective-config`; API-ключ не выводится.

Kokoro не импортируется и не прогревается, если эффективный движок — Piper, Edge, eSpeak NG или `none`. Автопрогрев Kokoro по умолчанию выключен; если выбран Kokoro, модель загружается при первом синтезе. После первого использования она может оставаться в памяти до выхода из процесса — это нормальное поведение кэшированной ONNX-сессии. Для низкого расхода RAM не выбирай Kokoro и держи `warmup_on_start = false`.

Логи содержат строку `PURAH ... TTS ... engine=...`. Проверь состояние конфигурации, окружения и реальные процессы:

```bash
./diagnose-tts.sh
```

Для проверки фактического синтеза и воспроизведения выбранным движком:

```bash
./.venv/bin/python test_tts_playback.py
```

Для принудительной диагностической проверки Kokoro (даже если в конфиге выбран другой движок):

```bash
PURAH_TTS_ENGINE=kokoro_ru ./.venv/bin/python test_tts_playback.py --kokoro
```

Оценивать расход памяти лучше на реально запущенном экземпляре. Потребление зависит от движка, модели wake-word, кэшей и версии библиотек. Суммарный RSS процессов полезен для грубой оценки, но может учитывать общие страницы памяти несколько раз; PSS точнее, если в системе доступен `smem`.

## Зрение по запросу

Скажи «Привет, Пура», затем «посмотри на экран» или «объясни ошибку на экране». PURAH снимает активное окно через `grim`, оставляя Quickshell HUD на месте, сжимает изображение в памяти и передаёт его эффективной `[vision]` модели. Скриншот не пишется на диск/в SQLite, но при облачном API изображение отправляется провайдеру. Поэтому перед запросом закрой личные сообщения, ключи и другие секреты.

## Исправление запуска Quickshell (1.1.2)

В предыдущей версии две ошибки мешали запуску: QML пытался вызвать `shell.readyFile.setText()`, хотя `readyFile` — локальный QML id, и относительная ссылка на SVG выходила за корень конфигурации Quickshell. Из-за этого launcher не получал `quickshell-ready` и завершался по таймауту, а Quickshell сообщал `qrc:/qs-blackhole`. Теперь handshake вызывает `readyFile.setText()` синхронно, а иконка загружается через абсолютный `file://` путь; копия SVG внутри корня QML служит безопасным fallback.

После обновления закрой старые экземпляры Quickshell/Purah и запусти `./start-purah.sh`. Если в логах ещё остались старые записи, это исторический лог; проверь, что новые строки после последнего запуска больше не содержат `shell.readyFile` или `qrc:/qs-blackhole`.

## Размытие стеклянного фона в Hyprland

В основном режиме PURAH — **layer**, namespace `purah-overlay`, а не обычное окно. Поэтому `windowrule` по `class = purah` на него не действует; этот релиз больше не создаёт Qt-окно даже при команде IPC `show`, пока включён layer-overlay режим. В версии 1.1.2 launcher больше не допускает скрытый Qt fallback в `start-purah.sh`/`run-purah.sh`: если `qs` не поднялся, он завершится, а не покажет обычное окно. <https://wiki.hypr.land/configuring/core/rules/layer-rules/>

Если в конфиге есть глобальное правило blur для всех слоёв, добавь правило **после глобального**. Если у тебя legacy-конфигурация `hyprland.conf` (hyprlang, поддерживаемая в Hyprland 0.56, но уже deprecated), подключи файл из проекта **после глобальных layer-правил**:

```ini
source = /home/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/Purah/hyprland-purah-rule.conf
```

Для новой Lua-конфигурации Hyprland 0.55+ добавь в `~/.config/hypr/hyprland.lua`:

```lua
dofile(os.getenv("HOME") .. "/Purah/hyprland-purah-rule.lua")
```

Lua-файл использует `hl.layer_rule` с `namespace = "^purah-overlay$"`, `blur = true` и `blur_popups = false`. В `.conf` используются соответствующие layer-эффекты `blur on, ignore_alpha 0.08` и `blurpopups off`; файловых правил `windowrule` для Purah больше нет. Quickshell `PanelWindow` находится в Wayland layer-shell `WlrLayer.Overlay`, а не среди обычных toplevel-окон. В актуальном Hyprland layer rules настраиваются через `hl.layer_rule`, поскольку Lua-конфигурация заменила hyprlang начиная с 0.55. <https://wiki.hypr.land/configuring/core/rules/layer-rules/>

Для проверки namespace запусти PURAH, открой глаз и выполни `hyprctl layers`; должен присутствовать `purah-overlay`. Если blur остаётся, проверь, нет ли следующего глобального layer-rule ниже него, переопределяющего правило. Launcher добавляет правило `blur on` при старте; правило в `hyprland-purah-rule.conf`/`.lua` должно быть подключено после глобальных правил.


## Управление активными окнами (Hyprland)

PURAH умеет работать не только с собственным shell: основной путь для GUI — `desktop_sequence`. Он адресно находит или запускает окно, переводит фокус через Hyprland, выполняет клавиатурную последовательность через `wtype`, останавливается при потере фокуса и затем возвращает прежнее окно. Это позволяет за один локальный tool-call выполнить сценарии вроде «открой Telegram и напиши в Избранное» или «выполни `ls` в выделенном терминале», без серии медленных раундов OCR и без движения мыши. `inspect_active_window` оставлен для неоднозначной проверки, а `click_in_active_window` с `ydotool` — резервный путь; в новом шаблоне `desktop.allow_mouse = false`.
Если optional Telegram-коннектор настроен, Saved Messages и каналы обслуживаются через API без GUI. GUI-путь с Ctrl+0 остаётся резервом для явной просьбы работать именно в Telegram Desktop; для уже открытого окна target должен быть `active`. Явная просьба открыть терминал использует `run_terminal_command(mode="visible")`, а не слепую серию кликов.

На Arch Linux `./install.sh` устанавливает `wtype`, `ydotool`, `tesseract` и языковые данные Tesseract `rus`/`eng`; `ydotool` и `ydotoold` нужны только для резервного мышиного пути. Установщик пытается включить пользовательский `ydotool.service`, но ошибка сервиса не блокирует установку. Для основной клавиатурной автоматизации через `desktop_sequence` достаточно `wtype`; в `~/.config/purah/config.toml` опции `[desktop].enabled` и `[desktop].allow_mouse` позволяют полностью отключить управление окнами или резервные клики.

Голосовой ввод не ослабляет условие wake-word: Пура принимает только завершённое распознавание заданной фразы, а не случайные partial hypotheses. После подтверждённой активации она сохраняет около 660 мс звука на переходе между двумя микрофонными потоками; VAD также хранит около 540 мс до обнаружения голоса. Стандартная пауза конца фразы увеличена до 1,15 с, а максимальная запись — до 45 с. В `[speech]` эти параметры доступны как `vad_threshold`, `end_silence_seconds`, `max_record_seconds` и `speech_start_timeout_seconds`; миграция меняет только прежние штатные значения и не перезаписывает пользовательские.

Эти инструменты работают от имени пользователя, поэтому доступ к текущему активному окну рассматривается как полноценное управление рабочим столом. Не отправляй сообщение, если активное приложение или адресат не подтверждены интерфейсом. Текст страницы и OCR не считаются инструкциями для ассистента.

## Память и проверка выбранного TTS

По коду Purah не должна загружать Kokoro, когда эффективный движок — `piper`, `edge`, `espeak_ng` или `none`: runtime Kokoro импортируется только внутри ветки `kokoro_ru`, а автопрогрев по умолчанию отключён. Piper-модель загружается при запуске синтеза, а eSpeak NG вызывается как отдельный системный процесс для фрагмента речи. После завершения синтеза RSS процесса может не сразу уменьшиться из-за поведения Python/ONNX Runtime; это само по себе ещё не доказывает, что продолжается синтез Kokoro.

2 ГБ для простого idle-процесса при выбранном Piper не стоит считать нормой, но из исходников нельзя достоверно определить, какой процесс именно ест память на твоём компьютере. Проверь сначала реальный конфиг, переменные и процессы:

```bash
./diagnose-tts.sh
```

В логе запуска должна быть строка `PURAH 1.1.3: TTS enabled=...; engine='piper'; voice='...ru_RU-irina-medium.onnx'` (или другой путь к выбранной модели), а не `engine='kokoro_ru'`. Посмотри RSS процессов:

```bash
ps -eo pid,ppid,rss,etimes,args --sort=-rss | grep -E '[m]ain.py --tray|[q]s -p .*/quickshell/purah'
```

RSS указан в KiB. Если установлен `smem`, смотри также PSS — RSS может несколько раз учитывать разделяемые библиотеки. Для сопоставления сравни показания до первого ответа, во время озвучки и после завершения; эти замеры нужно делать на твоей реальной сессии Hyprland.

## Requirements и проверка

- `requirements.txt` — только то, что импортирует ядро: PySide6 (окна, трей, мультимедиа), `sounddevice` и `numpy` (микрофон/VAD), `edge-tts` (сетевой TTS по умолчанию).
- `requirements-desktop.txt` — Python `websocket-client` для управляемых вкладок Firefox BiDi / Chromium CDP. `./install.sh` устанавливает его; CDP по умолчанию отключён. Сам AT-SPI (`python-gobject`, `at-spi2-core`), D-Bus (`glib2`) и `rg` ставятся системно через pacman.
- `requirements-wakeword.txt` — единственная дополнительная зависимость Vosk для локального wake-word; устанавливается отдельным `./setup_voice.sh`.
- `requirements-kokoro-ru.txt` — `onnxruntime` (локальная TTS-модель), Hugging Face downloader (первичная загрузка файлов), RUAccent, `espeakng-loader` и `phonemizer-fork` (русская фонемизация). `numpy` не дублируется: он уже в core. `misaki==0.9.4` специально устанавливается отдельно из `setup_kokoro_ru.sh`: у него устаревшее ограничение `python_requires` для Python 3.14, поэтому установщик делает точечный обход и сразу проверяет реальный G2P/smoke-test. Не запускай `pip install -r requirements-kokoro-ru.txt` вместо установщика.

Проверки проекта:

```bash
cd ~/Purah
./check.sh
```

Сборка проверяет синтаксис Python/shell, TOML, SVG, список файлов и тесты для TTS-текста, vision, Kokoro-контракта и установщика. В этой среде не установлены Quickshell/PySide GUI и физический микрофон, поэтому настоящий визуальный запуск overlay на твоём Hyprland после установки остаётся финальной проверкой.


## Полный доступ к системе и конфиг (1.2.0)

В `~/.config/purah/config.toml` явно заданные значения `[api]`, `[vision]`, `[tts]` и остальных секций побеждают переменные окружения, старый CHOOM env и файл `~/.config/purah/env`. Если конфиг некорректен или обязательный endpoint/model оставлен пустым, Purah остановится вместо тихого возврата к прежней модели. После изменений запусти `./start-purah.sh`: runtime fingerprint заставит приложение заменить устаревший backend. Эффективные endpoint и модели без ключей можно посмотреть через `./.venv/bin/python main.py --print-effective-config`.


## Промпт и чтение веб-страниц

Системный промпт вынесен в `system_prompt.md`. В `config.toml` задаётся только
`[assistant].system_prompt_file = "system_prompt.md"`; относительный путь считается
от каталога установленного приложения, абсолютный путь тоже поддерживается.
Для старых пользовательских конфигов с `system_prompt` встроенный текст сохраняется,
чтобы обновление не стирало пользовательские настройки.

Модель может вызвать инструмент `read_webpage` для чтения публичной HTTP(S)-страницы.
Загрузка ограничена по времени и размеру; скрипты и навигационные блоки удаляются.
Содержимое веб-страниц считается недоверенным вводом, а не инструкциями.
